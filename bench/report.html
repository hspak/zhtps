HTTP/2 · local loopback

September 14, 2026 · 84 audited trials · 171,517,473 verified responses · zero errors

In this earlier run, client and server ran on the same machine. Clients were pinned to separate physical cores, with no server/client SMT overlap. These are TLS loopback measurements and do not measure LAN capacity. The eight-worker ZHTPS results may still be limited by the client.

TLS 1.3 GET /, a verified six-byte ZHTPS\n response, persistent connections, and closed-loop requests. Each result is the median of three eight-second trials after two seconds of concurrent warmup. ZHTPS uses ReleaseSafe; every server receives the same CPU budget for its worker count.

Bun leads the serial case, while ZHTPS and Bun are nearly tied on one multiplexed connection. ZHTPS leads both multi-connection cases and every measured comparison with Go. Node and Bun use the same node:http2 fixture and run only in the one-worker comparison.

Both multi-connection cases allow 256 requests in flight. Go uses GOMAXPROCS equal to the server CPU count. Server CPUs are 0 through workers−1; the client pool is 8–15 and 24–31 on the same 16-core Ryzen AI Max+ 395. Node's 64 × 4 p99 varied from 3.34 to 12.70 ms; eight-worker ZHTPS at 8 × 32 ranged from 810,382 to 907,071 requests/s. These observed ranges are not confidence intervals.
